Пример небольшого pet-проекта на FastAPI с использованием RabbitMQ

Базовая идея: у нас есть веб-приложение (FastAPI), которое при обращении к эндпоинтам публикует сообщения в очередь RabbitMQ. Отдельный процесс читает сообщения из очереди и обрабатывает их.

###
Общая идея архитектуры
1. FastAPI-приложение:

    * Запускается на `uvicorn`.
    * Имеет несколько эндпоинтов: один для теста (`ping`), и другой для отправки сообщений в очередь.
    * Через библиотеку `pika` подключается к RabbitMQ и публикует сообщения.

2. RabbitMQ:

    * Запускается как сервис в `Docker`.
    * Хранит очередь, в которую приложение будет складывать сообщения.

3. Consumer:

    * Отдельный процесс в Python, который подписывается на ту же очередь и обрабатывает входящие сообщения.
    * Также использует `pika` для подключения к RabbitMQ.

4. Docker Compose:

    * Поднимает и RabbitMQ, и наше приложение единым набором команд (декларативно).

5. Prometheus:

    * `prometheus_fastapi_instrumentator`.
